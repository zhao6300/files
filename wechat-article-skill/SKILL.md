# 微信公众号写作与排版

这个 skill 有三部分：**想清楚**（选题、立论、取材），**写精炼**（为手机阅读写稿、改稿），**排好看**（能直接粘贴进公众号编辑器的排版）。
排版由 `scripts/md2wechat.py` 生成（零依赖，Python 3.8+）。

**质量底线**：内容好不好，比排版好不好重要得多。一篇文章如果说不出一句可以被反驳的核心判断，或者拿不出一条具名来源的证据，就不要急着排版，先回到第 2 步。

## 工作流程

### 1. 明确需求（信息不够时最多问 3 个问题）
- **主题与核心观点**：读者读完应该记住哪一句话？
- **读者是谁**：决定用词深浅和举例方式。
- **文体**：新闻 / 观点 / 清单 / 故事 / 教程 / 访谈，见 `templates/`。
- **篇幅**：默认 1500–2500 字（约 4–6 分钟阅读）；新闻快讯 600–1200 字。
- **账号调性**：据此选主题（见下表）。
- **用户手里有什么材料**：数据、采访、文件、亲身经历。一手材料是好文章最稀缺的部分，主动问。

用户已经给了完整稿子时，跳过写作，直接进入第 5 步“改稿”；只要排版时进入第 6 步。

### 2. 选题与立论（先读 `references/content-craft.md`）
- 用“新在哪里 / 和谁有关 / 我能多给什么”三问测试选题，大题目切小。
- 写一张**论点卡**：核心判断（≤40 字、可以被反驳）、为什么反直觉、最强证据、最强反方、读者收获。
- 用 `content-craft.md` 第 2 节的方法（拆数字、换参照系、二阶效应、利益相关方、追问机制、找反例、一线细节）找到**别人没写过的角度**，每篇至少用一种。

### 3. 取材与核实
- 涉及时效信息（数据、政策、产品、人事、价格）时，**先用联网搜索查证**，优先原始来源：公告、财报、统计数据、论文、当事人原话。
- 每个关键论点至少一条具名证据；记下来源名称和日期，文中写清楚“谁、何时、在哪说的”。
- **绝不编造**数据、引语、案例或来源。缺材料时用【待补：……】标注，交付时告诉用户需要补什么。

### 4. 先给骨架
写正文之前，先交付：
- 论点卡（第 2 步）
- 3–5 个备选标题（每个 ≤26 字，写法不同，优先给出判断或数字的标题，规则见 `references/writing-guide.md`）
- 摘要（≤120 字，要能单独吸引人，不是正文第一句）
- 章节大纲：3–5 个 `##` 小标题。**只读小标题就能看懂论证主线**
- 一句金句候选（必须是核心判断的凝练版本，不是修辞）

用户明确要求一次写完时，可以跳过确认，直接写。论点卡可以用 `<!-- -->` 注释写在稿子开头，不会进入正文。

### 5. 写正文，然后改稿
写之前**先读 `references/writing-guide.md`**。内容规则：
- **结论前置**：第一屏给出判断；新闻稿第一段写清谁、做了什么、为什么重要。
- **每一节只推进一步**，讲机制而不只讲现象；给最强的反方留位置。
- **用事实代替形容词**，用具名来源代替“有研究表明”“专家认为”。

手机阅读的硬性规则：
- 一段只讲一件事，**≤110 字**（手机上约 5 行）；多数段落 1–3 句。
- 每 300–500 字放一个视觉锚点：小标题、图片、`:::quote` 金句、列表、提示卡。
- 头三行就要抓住人：场景、冲突、数字或问题。不要用“随着……的发展”开头。
- 加粗每段最多一处，`==高亮==` 全文最多 3 处。
- 结尾：一句收束 + 一个具体的互动问题。**不要写诱导分享**（例如“转发才能领取”），违反平台规则。
- 外链会被自动转成文末脚注；文内提到来源时写清楚名称。
- **小标题**选一种写法并全文统一：短语式 6–12 字（清单、教程），或观点句式 ≤20 字（访谈、观点、深度稿，读者只扫小标题也能懂主线）。不要写“背景”“总结”这类空词。

**改稿三遍**（`content-craft.md` 第 5 节），每遍只做一件事：
1. **结构**：删掉不影响论证的段落，检查小标题串起来是否就是论证。
2. **段落**：删掉复述、预告、过渡句；每段只留一个意思。
3. **句子**：删套话和 AI 腔（“值得注意的是”“不仅……更是……”“赋能”），抽象词换成数字和例子。

终稿通常比初稿短 20%–30%。

### 6. 用组件排版
Markdown 语法和扩展组件见 `references/layout-system.md`。常用：

```markdown
---
title: 标题
author: 作者
theme: clay           # clay 陶土（默认）| mono 素白 | ink | celadon | amber | graphite
summary: 摘要，≤120 字
---

:::lead
导读：2–3 句，说清本文解决什么问题。
:::

## 小标题（自动编号）

:::quote 出处
一句值得截图转发的话。
:::

:::tip 小技巧
补充信息。
:::
```

**主推主题**（没有特别要求时，从这两套里选）：

| 主题 | 灵感 | 气质 | 适合 |
|---|---|---|---|
| `clay` 陶土（默认） | Claude | 燕麦纸色、陶土橙、宋体标题、衬线金句 | 观点、人文、AI 与科技随笔 |
| `mono` 素白 | OpenAI | 黑白灰、细线分章、大号无衬线金句、一点信号橙 | 技术、产品、AI、研究解读 |

**其他主题**：

| 主题 | 气质 | 适合 |
|---|---|---|
| `ink` 墨印 | 朱砂印章、汉字序号（壹贰叁） | 国风、人文、品牌故事 |
| `celadon` 青瓷 | 青绿釉色、斜体衬线数字 | 生活方式、读书、健康、教育 |
| `amber` 琥珀 | 杂志式 PART 标签、暖色 | 深度长文、商业、人物 |
| `graphite` 石墨 | 钢蓝、理性清晰 | 数据、教程 |

单篇文章的常用开关（写在 front matter 里）：`byline: 文丨某某  编辑丨某某` 署名行，`size: 16` 大字号，`h2: big` 40px 大序号，`bold: accent` 加粗句用主题色。访谈稿用 `:::qa 提问方` 包住问答部分。完整说明见 `references/layout-system.md`。头部账号的实测数据见 `references/benchmarks.md`。

两套主推主题的章节都用「01 / 05」形式的进度序号，读者在手机上随时知道读到了哪里。front matter 加 `paper: true` 可以给全文铺一层纸色底。

### 7. 检查、自评并生成
```bash
python scripts/md2wechat.py article.md --check     # 可读性检查
python scripts/md2wechat.py article.md             # 生成 article.html（手机预览 + 四主题切换 + 一键复制）
python scripts/md2wechat.py article.md --fragment  # 只输出可粘贴的 HTML 片段
```
**逐条处理 `--check` 的警告**，直到没有警告，或者能向用户说明为什么保留：
- 排版类：段落过长、标题过长、连续大段纯文字、表格列数过多、代码行过长、缺少摘要。
- 文风类：套话、AI 腔、模糊信源、空标题、感叹号过多。引用原话时可以保留；整篇都是转载原文时用 `--no-style`。

脚本只查得出表面问题。之后按 `content-craft.md` 第 7 节的 6 项评分表自评（信息增量 / 观点清晰 / 论证扎实 / 结构 / 精炼 / 准确）：**任一项低于 3 分或总分低于 24 分，先改稿**。

### 8. 交付
交给用户这些内容：
1. `article.md` 源稿，和 `article.html` 预览文件
2. 最终标题 + 2 个备选、摘要
3. 自评分数、最弱的一项，以及需要用户补充或核实的【待补】项和信源清单
4. 封面建议：主图 900×383（2.35:1），分享图 1:1。主体放在中间，因为分享时会裁成正方形。
5. 发布提示：在浏览器里打开 html，点「复制到公众号」，粘贴到编辑器；本地图片要在编辑器里重新上传。

## 排版原则（为什么这样设计）
- **正文 15px / 行高 1.85 / 字距 0.5px / 两端对齐**：参考头部账号实测（主流行高 1.75–1.87）并按 375pt 屏宽调校，每行约 21 个汉字。
- **全文只用一个强调色**，用在序号、标记、重点和链接上；正文用深灰，不用纯黑。
- **用留白分层级，而不是用框**：章节前留 56px，段落间距 20px，组件上下留 24–44px。
- **全部内联样式**：公众号会删掉 `<style>`、class、id 和脚本；也不使用 position、web 字体、外链。
- **兼顾深色模式**：背景只用低饱和的浅色，公众号自动反色后依然协调。
