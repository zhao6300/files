# 移动端写作指南

读者是在地铁上、排队时、睡前，用一只手拇指划着屏幕读你的文章。他们在**扫**，不是在**读**。下面每条规则都是为了让“扫”的人也能停下来。

## 1. 屏幕算术

| 参数 | 数值 | 含义 |
|---|---|---|
| 正文宽度 | ≈343pt | iPhone 标准屏减去公众号左右边距 |
| 每行字数 | 21–22 个汉字 | 按 15px 字号计算 |
| 一屏行数 | ≈16 行 | 行高 1.9 |
| 段落上限 | 110 字 ≈ 5 行 | 超过就成了“字墙” |
| 阅读速度 | ≈400 字/分钟 | 2000 字 ≈ 5 分钟 |

## 2. 标题（≤26 字，最好 14–22 字）

订阅号消息列表里标题最多显示两行，超出部分会被截断。好标题要满足下面至少一条：**具体、有反差、和读者有关、有信息量**。

| 写法 | 例子 |
|---|---|
| 数字 + 结果 | 只改了排版，完读率从 31% 涨到 52% |
| 反常识 | 越想写好的文章，越不该从开头写起 |
| 点名读者 | 写了 3 年公众号还没起色的人，大多卡在这一步 |
| 提问 | 为什么手机上的长文，越排越“透气”？ |
| 场景 | 凌晨两点改完第 9 版稿子，我删掉了一半 |

不要用：“震惊”“必看”“99% 的人不知道”，也不要把悬念留在标题里却在正文里不给答案。平台会限流这类标题，读者也会取关。

## 3. 摘要（≤120 字）

摘要会显示在分享卡片上。写成**单独也能看懂**的一句话：交代文章给读者什么好处，或者抛出核心冲突。不要直接复制正文第一句。

## 4. 开头（前 3 行定生死）

五种开头方式，选一种即可：
1. **场景**：“上周，一位做了 8 年公众号的朋友跟我说……”
2. **数字**：“同一篇稿子，完读率从 31% 涨到 52%。”
3. **冲突**：“所有人都说要写长文，可数据告诉我们……”
4. **提问**：“你有没有发现，越来越读不完一篇长文了？”
5. **结论先行**：直接把全文结论告诉读者，后文再展开论证。

不要这样开头：“随着……的发展”“众所周知”“在当今社会”，以及长篇自我介绍。

## 5. 正文

- **一段一个意思**。多数段落 1–3 句，偶尔用一句话单独成段制造停顿。
- **句子 ≤30 字**。长句拆短，少用“的的的”连续修饰。
- **每 300–500 字一个视觉锚点**：小标题、图、金句、列表、提示卡轮流用，不要连续使用同一种。
- **小标题要带信息**：写“行距是最便宜的高级感”，不要只写“行距”。各小标题句式尽量对仗。
- **加粗只标结论**，每段最多一处；`==高亮==` 全文最多 3 处，留给最想让人截图的句子。
- **并列信息用列表**，3–5 项最好；每项开头的词尽量保持相同句式。
- **用例子和数字代替形容词**：写“完读率涨了 21 个百分点”，不要写“效果非常显著”。
- **表格 ≤3 列**，更多维度就改成多个列表或卡片。
- **代码行 ≤40 字符**，超出部分在手机上要横向滑动才能看到。

## 6. 标点与格式

- 中文用全角标点；引号用“”，书名用《》，界面按钮等可用「」。
- 中英文、中文与数字之间留一个空格（脚本会自动处理，写作时也建议保持）。
- 数字用阿拉伯数字，百分比写作“31%”。
- 不要连续使用感叹号，全文最多出现 2 次。

## 7. 结尾

写作顺序：**一句收束 → 一个具体问题 → 轻量的行动引导**。

- 收束：用一句话回扣开头的问题或核心观点。
- 互动问题要具体，比如“你最受不了哪种排版？”；不要写“你怎么看？”这种泛泛的问题。
- 行动引导放在 `:::footer` 里，保持克制。

**合规红线**：不要诱导分享（“转发到朋友圈即可领取”“不转不是中国人”），不要诱导关注后才能阅读，不要虚构数据或来源。广告内容避免使用“最”“第一”“国家级”等《广告法》禁用的绝对化用语。

## 8. 常见文体骨架

参见 `templates/`：
- `opinion.md` 观点文：现象 → 反常识判断 → 3 个论据 → 边界与反驳 → 收束
- `listicle.md` 清单文：痛点 → N 条方法（每条：是什么 / 为什么 / 怎么做）→ 总结卡
- `tutorial.md` 教程文：结果预览 → 准备 → 分步 → 常见坑 → 延伸
- `story.md` 故事文：场景切入 → 冲突 → 转折 → 领悟 → 读者可迁移的启示
