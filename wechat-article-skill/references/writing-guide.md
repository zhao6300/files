# 移动端写作指南

读者是在地铁上、排队时、睡前，用一只手拇指划着屏幕读你的文章。他们在**扫**，不是在**读**。下面每条规则都是为了让“扫”的人也能停下来。

这份指南管“怎么写得好读”。“写什么、观点从哪来、证据够不够、怎么删”见 `content-craft.md`，先过那一关；“怎么写得像人、怎么去 AI 味”见 `human-voice.md`。

## 1. 屏幕算术

| 参数 | 数值 | 含义 |
|---|---|---|
| 正文宽度 | ≈343pt | iPhone 标准屏减去公众号左右边距 |
| 每行字数 | 21–22 个汉字 | 按 15px 字号计算 |
| 一屏行数 | ≈16 行 | 行高 1.85 |
| 段落上限 | 110 字 ≈ 5 行 | 超过就成了“字墙” |
| 阅读速度 | ≈400 字/分钟 | 2000 字 ≈ 5 分钟 |

## 2. 标题（≤26 字，最好 14–22 字）

订阅号消息列表里标题最多显示两行，超出部分会被截断。好标题要满足下面至少一条：**具体、有反差、和读者有关、有信息量**。

| 写法 | 例子 |
|---|---|
| 数字 + 结果 | 只改了排版，完读率从 31% 涨到 52% |
| 反常识 | 越想写好的文章，越不该从开头写起 |
| 点名读者 | 写了 3 年公众号还没起色的人，大多卡在这一步 |
| 提问 | 为什么手机上的长文，越排越“透气”？ |
| 场景 | 凌晨两点改完第 9 版稿子，我删掉了一半 |
| 判断句 | 价格战打到最后，赢家是供应链而不是品牌 |
| 新闻式 | 某公司裁员 15%，自动驾驶部门几乎撤空 |
| 栏目前缀 | 对话丨某创始人：战略的本质是不赌 |
| 人名 + 金句 | 某某：喜剧是乌托邦，公司是个厨子 |

头部账号最常用的是**判断句**和**新闻式**：标题本身就交代了结论或事实，读者不点开也能获得信息，点开是为了看论证。问句和悬念式偶尔用，不能是常态。

栏目前缀（“对话丨”“独家｜”）能帮老读者一眼认出栏目。可读性检查只把竖线之后的部分算作标题主体。

不要用：“震惊”“必看”“99% 的人不知道”，也不要把悬念留在标题里却在正文里不给答案。平台会限流这类标题，读者也会取关。

## 3. 摘要（≤120 字）

摘要会显示在分享卡片上。写成**单独也能看懂**的一句话：交代文章给读者什么好处，或者抛出核心冲突。不要直接复制正文第一句。

## 4. 开头（前 3 行定生死）

几种开头方式，选一种即可：
1. **场景**：“我手机里有 43 个没读完的标签页，最早的一个是去年 11 月打开的。”
2. **数字**：“同一篇稿子，完读率从 31% 涨到 52%。”
3. **冲突**：“所有人都说要写长文，可数据告诉我们……”
4. **提问**：问一个读者真的会问的具体问题，而不是“你是否也曾……”。
5. **结论先行**：直接把全文结论告诉读者，后文再展开论证。
6. **新闻导语**（新闻稿必须用）：一段 ≤80 字，写清谁、何时、做了什么、最重要的后果。例如：“9 月 28 日，某公司宣布裁员 15%，自动驾驶团队被整体撤销。这是它三年来第二次大规模收缩。”

不要这样开头：“随着……的发展”“众所周知”“在当今社会”“在这个信息爆炸的时代”，以及长篇自我介绍。

场景和数字**必须是真的**。编一个“上周一位朋友跟我说”，读者未必识破，但这正是最典型的 AI 开头。手里没有，就标【待补】问用户。

## 5. 正文

- **一段一个意思**。多数段落 1–3 句，偶尔用一句话单独成段制造停顿。段落长短也要有变化，不要每段都一样长。
- **句子多数 ≤30 字**，少用“的的的”连续修饰。但不要把每句都削成一样长：讲因果时一口气说完，要停顿时用几个字的短句。
- **每 300–500 字一个视觉锚点**：小标题、图、金句、列表、提示卡轮流用，不要连续使用同一种。
- **小标题要带信息**，二选一，全文统一：
  - **短语式**，6–12 字（少数派、远川的做法）：“选择健康的桌子和椅子”。适合清单、教程。
  - **观点句式**，≤20 字，可以写成两行（晚点的做法）：直接引用受访者或作者的判断。适合访谈、观点、深度稿。读者只扫小标题也能读懂主线。
  - 不要只写一个词，比如“行距”“背景”“总结”。
- **加粗只标结论**，每段最多一处；`==高亮==` 全文最多 3 处，留给最想让人截图的句子。
- **并列信息用列表**，3–5 项最好；每项开头的词尽量保持相同句式。
- **用例子和数字代替形容词**：写“完读率涨了 21 个百分点”，不要写“效果非常显著”。
- **表格 ≤3 列**，更多维度就改成多个列表或卡片。
- **代码行 ≤40 字符**，超出部分在手机上要横向滑动才能看到。

## 6. 标点与格式

- 中文用全角标点；引号用“”，书名用《》，界面按钮等可用「」。
- 中英文、中文与数字之间留一个空格（脚本会自动处理，写作时也建议保持）。
- 数字用阿拉伯数字，百分比写作“31%”。
- 不要连续使用感叹号，全文最多出现 2 次。

## 7. 结尾

写作顺序：**收束 → 一个具体问题（可选）→ 轻量的行动引导**。

- 收束：回到开头的那个场景，写它后来怎么样了；或者停在一个没解决的问题、一个接下来该看的信号上。不要总结全文，不要升华成人生道理，不要“希望对你有帮助”“让我们拭目以待”。
- 互动问题要具体，比如“你最受不了哪种排版？”；不要写“你怎么看？”这种泛泛的问题。
- 行动引导放在 `:::footer` 里，保持克制。

**合规红线**：不要诱导分享（“转发到朋友圈即可领取”“不转不是中国人”），不要诱导关注后才能阅读，不要虚构数据或来源。广告内容避免使用“最”“第一”“国家级”等《广告法》禁用的绝对化用语。

## 8. 访谈体

- 用 `:::qa 提问方` 包住问答部分。以“提问方：”开头的段落会渲染成问题（色块标签 + 粗体），以“某某：”开头的段落会把名字加粗。
- 先写 1–2 句背景导语，再写“以下是对话节选，经过删减”。
- 每个章节标题从受访者的原话里挑一句最有力的。
- 保留受访者说话的样子：口头禅、停顿、自我修正，删减时别把他改成书面语。人味在访谈里几乎全靠这个。
- front matter 写 `byline: 文丨某某  编辑丨某某`，建议加 `size: 16`。

## 9. 常见文体骨架

参见 `templates/`：
- `news.md` 新闻稿：导语（谁 / 何时 / 做了什么 / 为什么重要）→ 事实补全 → 影响 → 各方说法 → 接下来看什么
- `opinion.md` 观点文：论点卡 → 现象 → 流行解释 → 我的判断 → 3 个论据 → 最强反方与边界 → 收束
- `listicle.md` 清单文：痛点 → N 条方法（每条：是什么 / 为什么 / 怎么做）→ 总结卡
- `tutorial.md` 教程文：结果预览 → 准备 → 分步 → 常见坑 → 延伸
- `story.md` 故事文：场景切入 → 冲突 → 转折 → 后来 → 回到开头的场景（不讲道理）
- `interview.md` 访谈文：背景导语 → 观点句小标题 × 3–5（每节一段问答）→ 金句 → 收束
