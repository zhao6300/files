这是在 [根目录 20 页版本](../README.md) 之后重做的完整版：页面全部改为图形化版面（形状 + 连接线，无位图），补充了执行摘要、生活化类比、延迟预算专页与工作映射页，并为 34 页全部写了讲稿备注。

## 几个贯穿全篇的结论

- **TTFT ≠ Prefill 时间**：排队、调度、KV 读取、传输往往是更大的那一块。
- **平均值会骗人**：要看 p90 / p95 与达标率，并按上下文长度分桶，避免长请求被系统性牺牲。
- **KV 命中不一定更快**：深层（NVMe）恢复的搬运延迟可能反而导致 TTFT 违约。
- **Chunk 大小 / PD 配比不是性能参数**，而是在 TTFT 与 TPOT 之间分配延迟预算。
- **吞吐最高 ≠ Goodput 最高**：最终目标是在 SLO 约束下承载更多请求。

## 重新生成

```bash
pip install python-pptx
cd src && python build.py          # 生成 ../LLM-Inference-SLO-Goodput-v2.pptx
```

可选：逐页自检版式（溢出 / 越界 / 文字重叠）并刷新预览图。需要 Pillow 与一款中文字体：

```bash
cd src && python render.py         # 输出 ../preview/*.png 并打印警告
```

- 字体使用「微软雅黑 + Segoe UI」，在 Windows 上直接正常显示；macOS 上会回退字体，可在 `src/deckkit.py` 中把 `EA` 改为 `PingFang SC` 或 `Source Han Sans SC`。

- 页面中引用的实验数字（达标率 98% / 97%、干扰强度拟合 R² = 0.99、64K 长上下文案例）来自分享大纲，正式对外汇报前建议再核对原始出处的口径。
